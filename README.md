# Лабораторная работа № 2

Продолжение ЛР1: несколько труб и компрессорных станций, поиск и пакетные операции.

Открыть `anisimov_Lab2.slnx` в Visual Studio 2022 с компонентом разработки на C++.
Выбрать `Debug | x64`, запустить через `Ctrl+F5`. Используется C++17 и стандартная библиотека.

## Возможности

- Добавление труб и КС, просмотр всех объектов.
- Изменение ремонта трубы по ID, запуск и остановка цеха выбранной КС.
- Удаление трубы или КС по ID.
- Поиск труб по части названия или признаку ремонта.
- Поиск КС по части названия или минимальному проценту незадействованных цехов.
- После поиска труб: отправить в ремонт, вывести из ремонта или удалить все найденные трубы либо выбранные ID.
- Сохранение и загрузка по имени файла пользователя; поддерживаются русские буквы и пробелы.
- Журнал `log.txt`: только введённые пользователем строки, включая ошибочные, пустые строки и пробелы. Время, подсказки и сообщения программы не записываются. Записи предыдущих запусков сохраняются.

## Порядок работы

Пункты 1–2 добавляют объекты, пункт 3 показывает их ID. Пункты 4–5 изменяют выбранный объект,
пункт 9 удаляет его. В пункте 8 сначала выбираются тип объекта и фильтр.
Для пакетной операции можно выбрать все найденные трубы либо вводить их ID по одному;
`0` завершает выбор. Повторные ID и ID вне найденного множества отклоняются.

Поиск названия учитывает регистр. Процент простоя вычисляется как
`(всего цехов − работающих цехов) × 100.0 / всего цехов`; фильтр означает «не меньше указанного».

Для загрузки готового примера через пункт 7 ввести `../examples/lab2/both.txt`.
В пункте 6 можно указать новый файл, например `данные станции.txt`.
Если файл уже существует, его содержимое заменяется. Текущий журнал перезаписать нельзя.

## Хранение данных

`Pipe` и `CompressorStation` хранят только поля объектов. `Manager` управляет двумя
`unordered_map`: ID служит ключом и не дублируется в объекте. ID уникален в пределах типа:
труба № 1 и КС № 1 — разные объекты. После удаления ID не используется повторно в текущем запуске;
после загрузки следующий ID больше всех загруженных и ранее выданных в этом запуске.

Файл содержит количество труб, затем для каждой трубы ID, название, длину, диаметр и ремонт;
далее количество КС и для каждой ID, название, общее число цехов, число работающих цехов и класс.
Каждое значение записывается на отдельной строке. ID сохраняются, точность длины не теряется.

Загрузка заменяет коллекции. Если файл не удалось открыть, текущие объекты сохраняются.
Если содержимое некорректно, обе коллекции очищаются, как в исправленной ЛР1.
Чтение идёт непосредственно в объекты коллекций, без резервной копии всех данных.

Ввод чисел проверяется через `from_chars`; повторной проверки объектов перед сохранением нет.
Общие алгоритмы добавления, чтения, выбора ID и поиска используются для обоих типов.

# Лабораторная работа № 3

Продолжение ЛР2: соединение труб и компрессорных станций в газотранспортную сеть
и топологическая сортировка полученного ориентированного графа.

## Запуск

Открыть **`../anisimov_Lab3.slnx`** в Visual Studio 2022 с установленной разработкой на C++.
Выбрать `Debug | x64`, собрать решение (`Ctrl+Shift+B`), запустить (`Ctrl+F5`).
Рабочая папка при запуске из Visual Studio — `anisimov_Lab3`.
Используются C++17 и стандартная библиотека, сторонних библиотек нет.

ЛР2 сохранена: её проект `../anisimov_Lab2.slnx`, исходники `../anisimov_Lab2`
и примеры `../examples/lab2` не изменены. ЛР3 находится в отдельной папке и ветке `lab3`.

## Требования и реализация

1. КС — вершины графа, подключённые трубы — направленные рёбра.
2. Для соединения пользователь вводит ID КС входа, ID КС выхода и диаметр.
   Направление: **КС входа → труба → КС выхода**.
3. Из свободных труб указанного диаметра выбирается труба с наименьшим ID.
   Свободная труба — труба, которая ещё не используется ни в одном соединении.
4. Если подходящей свободной трубы нет, программа сразу переходит к её созданию:
   запрашивает название, длину и признак ремонта. Диаметр уже выбран и повторно не вводится.
   Созданная труба соединяет указанные КС.
5. Для ввода и загрузки труб разрешены только диаметры **500, 700, 1000 и 1400 мм**.
6. Топологическая сортировка выполняется алгоритмом Кана. Если есть цикл,
   программа сообщает, что сортировка невозможна, и не выводит частичный порядок.

ID обеих КС должны существовать; соединять КС с самой собой нельзя.
Одна труба может использоваться только в одном соединении. Несколько разных труб
могут соединять одну пару КС: алгоритм учитывает каждое ребро отдельно.
Циклические сети разрешено создавать и сохранять, но топологического порядка у них нет.

Сортировка включает все созданные КС, в том числе изолированные и находящиеся
в разных компонентах связности. Она выводит ID КС, а не ID труб.
Для каждого ребра его КС входа стоит раньше КС выхода. В общем случае допустимых
порядков несколько. При неизменной сети результат программы воспроизводим.

Ремонт трубы и работа цехов КС — свойства объектов: они не удаляют физическое
соединение и не исключают его из топологической сортировки.

## Меню

Пункты **1–9** сохранены из ЛР2: создание, просмотр, редактирование, сохранение,
загрузка, поиск, пакетные операции и удаление объектов. Новые пункты:

| Пункт | Действие |
| --- | --- |
| 10 | Соединить КС трубой по диаметру |
| 11 | Показать трубы сети, направление, ID и названия КС |
| 12 | Вывести топологический порядок КС или сообщение о цикле |
| 13 | Отсоединить трубу по её ID, сохранив саму трубу |
| 0 | Завершить программу |

`0` при выборе ID отменяет действие. Неверные ID и числа запрашиваются повторно.
При удалении трубы, в том числе пакетном, её соединение удаляется.
При удалении КС удаляются все входящие и исходящие соединения; сами трубы сохраняются
и становятся свободными. Пункт 13 позволяет изменить сеть без удаления объектов.

## Файлы и журнал

Пункты 6–7 сохраняют и загружают **и объекты, и сеть**. Формат объектов сохранён из ЛР2:
количество труб, записи труб, количество КС, записи КС. После них ЛР3 добавляет раздел:

```text
NETWORK_V1
количество соединений
ID трубы
ID КС входа
ID КС выхода
...
```

Каждое значение занимает отдельную строку. ID, параметры и направления сохраняются.
При загрузке проверяются существование объектов, уникальность использования трубы,
диаметры, корректность чисел и отсутствие лишних или неполных данных.
Файлы ЛР2 без раздела сети загружаются как набор объектов без соединений, если диаметры
соответствуют ограничению ЛР3. Файлы ЛР3 следует открывать программой ЛР3.

Как в ЛР2: если файл не открывается, текущие данные остаются; если содержимое неверно,
объекты и сеть очищаются. Загрузка заменяет текущую сеть. Новые ID не повторяют ранее
выданные или загруженные ID в пределах текущего запуска.

`log.txt` содержит **только введённые с клавиатуры строки**, включая ошибочные,
пустые строки и пробелы. Время, подсказки, сообщения программы и содержимое загружаемых
файлов туда не попадают. Строки записываются сразу после чтения, до проверки.
Журнал дополняется при следующих запусках; его перезапись через пункт 6 запрещена.

## Устройство программы

- `main.cpp` — меню и запуск действий.
- `Manager` — коллекции объектов, ввод команд, выбор свободной трубы, проверка файлов.
- `Pipe`, `CompressorStation` — параметры и операции соответствующих объектов.
- `GasNetwork` — связи по ID труб, отсоединение и топологическая сортировка.
- `Utils` — проверка ввода и запись исходных строк пользователя в журнал.

В алгоритме Кана строятся списки смежности и число входящих рёбер для каждой КС.
КС без входящих рёбер попадают в очередь. Из очереди извлекается КС, добавляется
в результат, затем уменьшается число входящих рёбер её соседей. Сосед с нулевым
числом входящих рёбер попадает в очередь. Если обработаны не все КС — остался цикл.
Алгоритм использует в среднем `O(V + E)` времени и `O(V + E)` памяти;
подготовительная сортировка ID в `Manager` занимает `O(V log V)`.

## Автоматические проверки

Из корня репозитория после сборки, с установленным Python 3:

```text
python tests/lab3/check_lab3.py x64/Debug/anisimov_Lab3.exe
python tests/lab3/check_lab3.py x64/Release/anisimov_Lab3.exe
```

Проверяются ввод и автоматическое создание труб, все четыре диаметра, занятые трубы,
отмена, EOF, удаление и повторное использование труб, сохранение и загрузка сети,
совместимость с ЛР2, отклонение повреждённых файлов и чистота журнала.
Порядок проверяется по всем рёбрам; для случайных графов наличие цикла независимо
проверяется обходом в глубину. Есть цепочка и цикл из 2000 КС.
